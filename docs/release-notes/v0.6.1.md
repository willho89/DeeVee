A bug-fix release of **DeeVee**, the DVD-Video player core for RetroArch.

> **Alpha.** Still tested on a handful of discs and mostly on one machine (a Steam Deck). Reports are welcome.

## Fixed

- **Damaged disc images no longer restart the disc.** An image with unreadable sectors, such as one rescued from a disc with disc rot, used to jump back to the start of the disc when playback reached the damage. DeeVee treated the read error as the end of the disc, and the default End of Disc setting is *Restart*. Now it skips ahead to the next readable part, about half a second further on, and keeps playing. You'll see a short glitch where the data is missing. If a stretch is damaged too badly to skip, playback stops there as before.

## Verified since 0.6.0

- **CSS decryption on a genuinely encrypted disc image.** This is a raw image of a retail disc, played with the distributed core (libdvdcss loaded from RetroArch's system folder). Without libdvdcss, the disc stops with the on-screen message naming the file to install. With it, the disc's keys are recovered from the image and the disc plays with no decoding errors.

Each zip contains the core, `deevee_libretro.info` and `INSTALL.txt`. To upgrade, replace the core in RetroArch's `cores` folder and the `.info` file in its `info` folder. On Android, use *Load Core → Install or Restore a Core* instead.

## Encrypted discs

DeeVee doesn't include CSS decryption. Decrypted rips, such as MakeMKV ISOs, play as they are. For CSS-encrypted images, put **libdvdcss** in RetroArch's **system** folder, the same place BIOS files go: `libdvdcss.so.2` on Linux and Android, `libdvdcss-2.dll` on Windows, `libdvdcss.2.dylib` on macOS.

## Testing status

- **Test suite:** passes on Linux x86_64, Windows (under Wine), macOS arm64 and macOS x86_64 in CI, and on Linux arm64/armhf under QEMU. It now includes a damaged-image test, which fails on 0.6.0.
- **Not yet verified:**
  - Real PAL discs, multi-angle discs, and discs with separate menus per TV type.
  - Android on a real device. The Android cores build, but nobody has run them yet.
  - Windows outside Wine, and real Raspberry Pi hardware.
- **Not supported:** physical DVD drives, Blu-ray and DVD-Audio.
